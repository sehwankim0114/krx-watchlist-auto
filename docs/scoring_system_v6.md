# 한국 주식 자동화 분석표 v6 점수체계 확정본

- 문서 버전: `2026-07-01-v6.0-score-policy`
- 적용 대상: 관종표, 분석표, 코피표, 코피표1개월, 코닥표, 코닥표1개월, 코급표, 월사이클표, 단상표, 환율약세표, 시장상태표, 보유종목표, 미관종표
- 목적: 실제 계산 항목, 점수, 추천 문구, 주의 문구를 서로 일치시킨다.
- 핵심 원칙: 점수를 높여 보이게 하지 않고, 실제 투자 적합성을 더 정확하게 평가한다.

---

## 1. 기존 점수와 최종 점수의 구분

기존 `collect_universe.py`의 가격·거래대금·변동성·시가총액 중심 점수는 v6 전환 기간에만 다음 이름으로 보존한다.

- 기존 `score` → `legacy_market_score`
- 기존 `reason` → `legacy_market_reason`

기존 점수를 다음 표현으로 부르지 않는다.

- 기업가치 종합점수
- 실적 종합점수
- 밸류에이션 종합점수
- 최종 투자점수

기업실적·밸류에이션·수급 자료가 연결되기 전까지 기존 점수는 후보 정렬을 위한 임시 시장점수일 뿐이다.

## 2. 최종 100점 구성

| 평가영역 | 배점 | 실제 평가자료 |
|---|---:|---|
| 실적·재무건전성 | 30점 | 매출, 영업이익, 순이익, 영업이익률, ROE, 부채비율, 영업현금흐름 |
| 밸류에이션 | 20점 | PER, PBR, PSR, EV/EBITDA, 업종·과거 대비 수준 |
| 성장성·기업가치 | 15점 | 3년 성장률, 최근 분기 가속도, 이익지속성, 순현금·기업가치 |
| 가격흐름·현재위치 | 15점 | 1개월·3개월 수익률, 기간 저가·고가 대비 위치, 과열 여부 |
| 거래활발·가격탄력 | 10점 | 20일 평균 거래대금, 거래량, 하루평균 절대등락률 |
| 수급·공시부담 | 10점 | 유상증자, CB·BW·EB, 보호예수, 블록딜, 대주주 매도, 오버행 |
| **합계** | **100점** |  |

각 영역 점수는 0점보다 낮아지거나 배점보다 높아질 수 없다.

## 3. 세부 배점

### 3.1 실적·재무건전성 30점

| 항목 | 배점 |
|---|---:|
| 매출 성장과 안정성 | 5점 |
| 영업이익 성장과 흑자 여부 | 7점 |
| 순이익 흐름 | 3점 |
| 영업이익률 | 4점 |
| ROE | 4점 |
| 부채비율 | 3점 |
| 영업현금흐름 | 4점 |
| **합계** | **30점** |

영업손실이 확인되면 `operating_loss_flag=true`로 저장하고 종목명 왼쪽에 `-`를 표시한다.

### 3.2 밸류에이션 20점

| 항목 | 배점 |
|---|---:|
| PER | 8점 |
| PBR | 5점 |
| EV/EBITDA | 4점 |
| PSR 또는 대체 가치지표 | 3점 |
| **합계** | **20점** |

PER가 음수이거나 의미가 없으면 무조건 저평가로 판정하지 않는다. 적자기업은 PER 점수를 제한하고 실적 상태를 함께 설명한다.

### 3.3 성장성·기업가치 15점

| 항목 | 배점 |
|---|---:|
| 최근 3년 매출 성장률 | 4점 |
| 최근 3년 영업이익 성장률 | 4점 |
| 최근 분기 실적 가속·둔화 | 3점 |
| 흑자 지속성과 이익 안정성 | 2점 |
| 순현금·기업가치 상태 | 2점 |
| **합계** | **15점** |

### 3.4 가격흐름·현재위치 15점

| 항목 | 배점 |
|---|---:|
| 1개월 가격흐름 | 4점 |
| 3개월 가격흐름 | 3점 |
| 기간 저가·고가 대비 현재위치 | 5점 |
| 과열·급락 위험 | 3점 |
| **합계** | **15점** |

고점권에 있다는 이유만으로 기업가치 점수를 낮추지 않는다. 가격영역에서만 과열·추격매수 위험을 반영한다.

### 3.5 거래활발·가격탄력 10점

| 항목 | 배점 |
|---|---:|
| 20일 평균 거래대금과 거래량 | 6점 |
| 하루평균 절대등락률 | 4점 |
| **합계** | **10점** |

거래활발과 가격탄력은 서로 다른 개념으로 저장한다.

- 거래활발: 주문 체결과 매매 편의
- 가격탄력: 하루 가격 움직임의 크기
- 탄력이 높다고 반드시 좋은 종목은 아니다.
- 변동이 지나치게 크면 `탄력 불안정`으로 표시한다.

### 3.6 수급·공시부담 10점

실제 부담이 확인되지 않으면 10점에서 시작한다. 실제 확인된 부담의 종류·규모·시점을 근거로 감점한다.

| 실제 부담 수준 | 점수 범위 |
|---|---:|
| 없음 | 9~10점 |
| 주의 | 6~8점 |
| 경계 | 3~5점 |
| 위험 | 0~2점 |

`CHECK_LIMITED`, API 오류, 조회 제한은 실제 수급부담으로 간주하지 않는다.

## 5. 자료 부족 처리

### READY

다음 조건을 모두 충족한 경우다.

- 가격자료 정상
- 핵심 실적자료 정상
- 핵심 밸류에이션 자료 정상
- 수급확인 상태가 `OK`
- 세부점수 합계와 총점이 일치

표시:

```text
score_status = READY
score_total = 0~100
```

### LIMITED

다음 중 하나라도 해당하면 최종점수를 확정하지 않는다.

- 최근 실적자료 미확보
- PER·PBR 등 핵심 밸류에이션 자료 미확보
- 기업 식별 실패
- 핵심 데이터의 기준일 불일치
- 수급 확인 범위가 지나치게 제한됨

표시:

```text
score_status = LIMITED
score_total = null
score_recommendation = 자료보완 후 판단
```

이때 가격자료만으로 계산한 임시 값은 `legacy_market_score`로만 남기며 최종점수처럼 표시하지 않는다.

### FAILED

계산식 오류, 데이터 파손, 필수 열 누락 등으로 평가 자체가 실패한 경우다.

```text
score_status = FAILED
score_total = null
score_recommendation = 평가오류
```

---

## 6. 최종점수에 따른 기본 판정

자료상태가 `READY`인 경우에만 사용한다.

| 최종점수 | 기본 판정 |
|---:|---|
| 85~100점 | 핵심추천 후보 |
| 75~84.9점 | 추천 후보 |
| 65~74.9점 | 관찰 후보 |
| 55~64.9점 | 대기·중립 |
| 0~54.9점 | 주의 |

다음 조건이 있으면 높은 점수라도 추천을 제한할 수 있다.

- 실제 수급부담 `위험`
- 영업손실 지속
- 현재위치 `고점권과열`
- 거래활발 `매우부족`
- 데이터 기준일 불일치
- 요청시점 가격 확인 실패

추천 제한 사유는 반드시 `score_warning_reasons`와 표의 `점수·추천·주의사유`에 함께 표시한다.

## 7. 설명문 생성 원칙

설명문은 실제 점수 구성과 같은 자료만 언급한다.

올바른 예:

```text
82점 / 매출과 영업이익이 증가하고 부채 부담은 낮습니다.
업종 대비 PER은 보통이며, 현재가는 3개월 중상단권이어서
추격매수보다 가치매수구간 대기가 적절합니다.
```

잘못된 예:

```text
기업가치가 우수합니다.
```

재무·밸류에이션 자료를 실제로 계산하지 않았다면 위 표현을 사용하지 않는다.

설명문 순서:

1. 총점과 자료상태
2. 실적·재무 핵심
3. 밸류에이션 핵심
4. 가격위치와 매수 판단
5. 실제 수급·공시 주의사항
6. 자료제한 사항

---

## 8. 요청시점 가격 반영

요청시점 현재가가 확보되면 다음 항목을 다시 계산한다.

- 현재위치
- 가격흐름·현재위치 점수
- 가치매수구간 진입 여부
- 익절가 접근 여부
- 과열·추격매수 위험
- 최종점수
- 기본 판정
- 점수 설명문

다음 항목은 요청시점 가격만으로 변경하지 않는다.

- 확정 재무실적
- 확정 밸류에이션 기준자료
- 실제 공시 내용
- 실제 수급부담
- 영업손실 여부

요청시점 가격 확인에 실패하면 직전 공식가격을 사용하되, 반드시 `요청시점 가격 미확인`이라고 표시한다.

## 9. 검증 규칙

자동화는 다음을 검사한다.

```text
score_financial 최대 30
score_valuation 최대 20
score_growth_value 최대 15
score_price_position 최대 15
score_liquidity_elasticity 최대 10
score_supply_disclosure 최대 10
score_total 최대 100
```

`READY`인 모든 종목은 다음 식을 만족해야 한다.

```text
score_total =
score_financial
+ score_valuation
+ score_growth_value
+ score_price_position
+ score_liquidity_elasticity
+ score_supply_disclosure
```

허용 오차는 반올림을 고려하여 0.1점 이하로 한다.

다음 오류가 하나라도 있으면 API 최종상태를 `READY`로 만들지 않는다.

- 합계 불일치
- 영역별 최대점수 초과
- `LIMITED`인데 총점 표시
- `CHECK_LIMITED`를 실제 수급부담으로 표시
- 설명문에 계산하지 않은 지표 언급
- 기존 임시 시장점수를 최종점수로 표시

## 10. 전환 순서

1. 이 점수정책 문서를 GitHub에 확정한다.
2. 기존 `score`를 `legacy_market_score`로 분리한다.
3. 기업실적·밸류에이션 API를 추가한다.
4. 수급확인 상태와 실제 부담을 분리한다.
5. v6 최종점수 계산기를 연결한다.
6. 요청시점 가격 후 점수·설명을 재생성한다.
7. 13개 표에 동일한 점수 필드를 연결한다.
8. GitHub와 Custom GPT 설명을 동일하게 맞춘다.

## 11. 사용자 표시 형식

표의 점수는 별도 열로 늘리지 않고 `점수·추천·주의사유` 칸 앞부분에 넣는다.

예시:

```text
82점 · 추천
실적 증가와 재무건전성은 양호합니다.
현재는 3개월 중상단권으로 눌림 대기가 적절합니다.
```

자료가 부족한 경우:

```text
평가제한
최근 실적·밸류에이션 자료가 부족하여 최종점수를 확정하지 않았습니다.
가격흐름만으로 추천하지 않습니다.
```
