# V8.5.3 새 양식 기본 검색 연결

코피표·연속하락표·2.4연속하락표의 새 19열 양식과 검증된 공식 일봉 지표를 기본 검색에 연결한다. 독립 스윙표는 보류한다. 이는 모든 지표의 완성이나 실제 GPT 출력 검사 완료를 뜻하지 않는다.

## 범위와 보존

- Worker V1.4.0 소스·배포는 그대로 사용한다. 기존 구형 API도 회귀검사용/이전 클라이언트용으로 유지하되 새 GPT는 코피표를 그 경로로 호출하지 않는다.
- 기존 getKospiWatchlist operationId 하나의 경로를 `/tables/v1/{table}`로 변경한다. table=kospi/decliners/decliners24; operationId는 30개를 유지한다. 30개는 이 프로젝트의 호환성 선택이지 OpenAI 공식 한도라고 주장하지 않는다.
- 기존 13명령 계약에 `two_table_release` 확장으로 2명령을 추가하여 유효 명령은 15개다. 코피표 핵심 라우트 자체도 새 경로/매개변수로 전환한다.
- 명시적 config/two_table_release.json과 최신성 검사를 모두 통과해야 새 READY 페이지를 게시한다. stale/sync 실패에서는 활성화 false·무효 상태를 게시하고 Worker가 차단한다. 새 페이지를 만들지 못한 CI는 푸시하지 않는다.
- V850 계산/미제공 정책과 V851 비활성 게시기 및 기존 테스트를 유지한다. V853은 실제 파일 해시·크기·운영 메타데이터를 먼저 검사한 후 별도 임시 투영으로 V851의 종목·선별·순서·필드 검증도 모두 실행한다.
- V852 Worker 비활성 회귀는 메모리에서 명시적으로 만든 비활성 fixture로 유지한다. 별도 V853 검사는 실제 생성 운영 데이터의 전체 페이지를 V1.4.0 소스에 넣어 기본 production 경로를 검사한다. 인터넷 실배포 검사는 안전감사에서 별도로 한다.

## 완성되지 않은 지표

투자종합점수100, 실적전망 변화, 업종 상대강도, 확정 스윙저점 손절은 계속 null이다. 이 열을 지우거나 구형 점수122~137을 환산/잘라내기 하지 않는다. `PARTIAL_DECLARED`를 모든 페이지에 표시하며 가격만으로 우선매수 아이콘을 부여하지 않는다. 20일선은 근거일이 있는 참고값으로만 표시한다. 신호·가격범위는 투자 참고자료이지 체결 지시가 아니다.

## 검증

Python 계산40·shadow23·Worker건강8·release14 테스트, 기존 Worker 회귀 및 비활성36·운영8 테스트를 함께 실행한다. 별도 클라이언트 검사에서 단일 도메인, 기존30 operationId, 정확한3가지 path enum, 배열 응답 스키마, 19열, 지침8,000자 이내, 미제공 정책을 확인한다.

OpenAI 공식 [운영 문서](https://developers.openai.com/api/docs/actions/production)의 응답 제한·설명 길이를 확인했다. 프로젝트는 페이지30행/최종30KB 제한과 45초 이내 응답을 사용하며, 새 원본 페이지는28.5KB 이하로 transport 여유를 둔다. 편집 화면의 실제 저장·호출은 수동 종단검사로 확인한다.

## 운영 적용

1. 제공된 installer와 safe-repository-cleanup.yml을 수동 업로드한다. GitHub App의 workflows 권한 제한 때문에 installer가 워크플로 파일을 푸시하지 않는다.
2. installer는 현재 소스 SHA를 확인하고 소스와 동기화 API를 한 커밋으로 게시한다. 원격 main이 작업 도중 바뀌면 푸시하지 않고 재실행을 요구한다. 오래된 API를 강제로 최신 처리하지 않는다.
3. 성공 후 GPT의 기존 단일 Action 스키마와 전체 지침을 대응 파일로 교체한다. 새 Action 세트를 중복 추가하거나 Worker를 재배포하지 않는다.
4. 완료한 installer만 삭제하고 새 읽기 전용 안전감사를 실행한다. 이 삭제는 Git 기록에서 복구 가능하다.
5. GPT 새 대화에서 코피표, 2.4연속하락표, 연속하락표를 각각 검사한다. 실제 출력 전까지 수동 GPT 전환/표 출력 완료라고 선언하지 않는다.

새 빌드 중 생성 페이지가 줄어드는 경우 소유권을 검증한 해당 api/two_table_v1의 오래된 페이지 파일만 제거한다. 임의 사용자 파일·원자료·보유정보는 삭제하지 않는다.
